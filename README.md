# YouTube Proxy для Android TV

Нативное приложение под Android TV (проверялось на Xiaomi Mi Stick 4K): поднимает
VPN и пускает **только выбранные приложения** через прокси-ноды, экспортированные
из macOS-приложения.

```
Dist/YouTubeProxy-TV-1.2.0.apk   arm64-v8a + armeabi-v7a, minSdk 23, targetSdk 30
```

## Установка

1. На телевизоре включить отладку: «Настройки → Система → Сведения → 7 раз по
   «Сборка» → Для разработчиков → Отладка по сети».
2. С Mac:

```
adb connect <ip-телевизора>:5555
adb install -r Dist/YouTubeProxy-TV-1.2.0.apk
```

Либо скопировать APK на флешку и открыть файловым менеджером (`Downloader`).

## Как работает

```
приложение → TUN (VpnService) → hev-socks5-tunnel → 127.0.0.1:SOCKS5
                                                        │
                                    наш SOCKS5-сервер (protect)
                                                        │
                                          удалённая нода (HTTP/SOCKS5)
```

Ключевой момент: `hev-socks5-tunnel` умеет только SOCKS5 и создаёт исходящие
соединения сам — внутри VPN они попали бы обратно в туннель. Поэтому соединения
к нодам открывает наш собственный SOCKS5-сервер, и каждое проходит через
`VpnService.protect()`.

## Только выбранные приложения

По умолчанию включены приложения YouTube (`com.google.android.youtube.tv`).
Кнопка «Приложения для VPN» открывает список установленных приложений с
отметками — выбранные попадают в `addAllowedApplication`, остальной трафик
телевизора идёт напрямую. Пустой выбор означает «все приложения».

## Подписка

На экране есть поле URL подписки и две кнопки:

- **«Вставить»** — берёт ссылку из буфера обмена. Пультом вводить URL неудобно,
  поэтому основной способ добавления подписки — скопировать ссылку на телефоне
  или Mac и нажать «Вставить» (буфер обмена на Android TV общий для приложений).
- **«Загрузить»** — скачивает подписку, разбирает ноды и сохраняет их.

Ссылку можно и набрать вручную, если подключена клавиатура.

Поддерживаются `socks5://` и `http(s)://` (в том числе base64-подписки). Схемы
`vless://`, `vmess://`, `trojan://`, `ss://` пропускаются: для них нужны ядра
sing-box/Xray, которых в ТВ-сборке пока нет. Если в подписке не нашлось ни одной
подходящей ноды, приложение покажет ошибку, а не пустой список.

Скачанные ноды хранятся в `filesDir/nodes.txt` и имеют приоритет над встроенным
`app/src/main/assets/nodes.txt` (экспорт из macOS-приложения).

## Сборка

Нужны JDK 25, Android SDK (platform 36, build-tools 36, NDK 28.2.13676358):

```
export JAVA_HOME=<jdk-25>
export ANDROID_HOME=$HOME/Library/Android/sdk
export GRADLE_USER_HOME=$PWD/.gradle-home
gradle :app:assembleRelease
```

Ключ подписи создаётся локально:

```
keytool -genkeypair -keystore keystore/mistick.jks -storepass mistick123 \
  -keypass mistick123 -alias mistick -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=MiStick Proxy, OU=Dev, O=Local, C=RU"
```

## Автоматическое переключение нод

- Ноды хранятся в пуле с состоянием: проверена ли, какая задержка, сколько сбоев.
- Сбойная нода уходит в экспоненциальную паузу (30 с → 15 мин), запрос сразу
  пробует следующую — пользователь видит только задержку, а не обрыв.
- Каждые 45 секунд текущая нода проверяется настоящим TLS-рукопожатием с
  `www.youtube.com` через неё. Не прошла — сервис сам выбирает рабочую из пула и
  пишет об этом в статус («переключений: N»).
- Счётчик переключений и текущая нода видны в строке состояния и в уведомлении.

## Ядра: sing-box и Xray

На экране есть выбор ядра: «Ядро sing-box», «Ядро Xray» (или ни одного — тогда
работает пул socks5/http нод). Ядро запускается отдельным процессом и поднимает
локальный вход; наш SOCKS5-сервер ходит в него как в обычную ноду.

- **Бинарники не встраиваются в APK** (sing-box — 73–79 МБ, Xray — 32 МБ):
  скачиваются при первом запуске под ABI устройства в `filesDir/bin/`.
- **sing-box**: есть под arm64-v8a и armeabi-v7a.
- **Xray**: только arm64-v8a (официальной сборки под 32-битный ARM нет) — на
  32-битных ТВ выбирайте sing-box.
- Подписка для ядер — **JSON** (sing-box/clash: `outbounds`/`proxies`). Share-ссылки
  (`vless://`, `vmess://`, …) для ядер не конвертируются: они остаются в пуле
  socks5/http. Кнопка «Загрузить» сохраняет и сырой JSON, и socks-ноды.
- Конфиг строится пачками по 200 нод (как в macOS-версии), чтобы не подвешивать
  приложение; отбраковка битых outbounds — самим ядром.
- Запуск ядра вынесен в отдельный поток: скачивание и старт не блокируют интерфейс.

## Маршрутизация по сервисам

Под кнопками — переключатели: YouTube, ChatGPT, Telegram, WhatsApp, GitHub и
«Всё». Отмеченные сервисы идут через прокси-ноду, остальной трафик открывается
напрямую (сокет проходит `VpnService.protect()`, поэтому не зацикливается в TUN).
По умолчанию выбран только YouTube. Настройка сохраняется между запусками.

## Проверка доступа

Кнопка «Проверить доступ» проверяет пять сервисов — YouTube, ChatGPT, Telegram,
GitHub, WhatsApp. Если VPN запущен, проверка идёт **через локальный SOCKS5**, то
есть тем же путём, что и трафик приложений; если выключен — напрямую. Результат
показывается строками: «OK · N мс», «регион» (ChatGPT отвечает 403) или
«нет ответа».

## Совместимость

APK содержит обе архитектуры (arm64-v8a и armeabi-v7a): часть Android TV устройств
на Amlogic работает с 32-битным userspace, и сборка только под arm64 не ставится.
`screenOrientation="landscape"` убран — он добавлял обязательное требование
`android.hardware.screen.landscape`, из-за которого установщик мог отказать.

## Ограничения

- Только arm64-v8a (Mi Stick 4K подходит).
- UDP-трафик проксируется по TCP и на бесплатных нодах обычно не работает;
  YouTube переключится на TCP.
- Ноды публичные: скорость и живучесть ограничены, трафик видит владелец ноды.
- `targetSdk 30` — для сайдлоада; для Google Play потребуется 34+ и
  foregroundServiceType.
